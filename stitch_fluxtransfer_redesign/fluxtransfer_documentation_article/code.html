How it works

Discover the technical foundation of FluxTransfer's peer-to-peer architecture and understand how we achieve secure, zero-knowledge data transfers across devices.

schedule Last updated: Oct 26, 2024
timer 5 min read

The P2P Architecture

At its core, FluxTransfer establishes a direct WebRTC connection between the sender and receiver. This means your data never rests on our servers. When a transfer is initiated, our signaling server briefly coordinates the connection metadata, and then steps out of the way entirely.

lightbulb

Direct Connection Benefit

Because data flows directly between peers, transfer speeds are limited only by the slower of the two local network connections, completely bypassing external bandwidth bottlenecks.

End-to-End Encryption

Security is not an add-on; it is the foundation. Every byte transferred through the direct channel is encrypted using AES-GCM-256.

  • check_circle Key Generation: Ephemeral keys are generated locally on the sender's device.
  • check_circle Exchange: Keys are exchanged via the secure WebRTC data channel handshake.
  • check_circle Zero-Knowledge: FluxTransfer servers mathematically cannot decrypt the payload.

Frequently Asked Technical Questions

What happens if the connection drops? expand_more
The protocol includes auto-resume capabilities. If a temporary network partition occurs, the data channel maintains its state for up to 60 seconds. Upon reconnection within that window, the transfer resumes from the last acknowledged byte chunk.
Are there file size limits? expand_more
Theoretically, no. WebRTC data channels can handle streaming large blobs. However, to maintain browser memory stability during stream buffering, we recommend keeping individual files under 100GB.
How does signaling work over restrictive NATs? expand_more
We utilize a global fleet of TURN relays. If a direct STUN connection fails due to symmetric NATs on both ends, the connection gracefully falls back to a TURN relay, maintaining end-to-end encryption while ensuring connectivity.
